# README Requirements

Use this reference whenever a repository is created, its setup changes, or its supported platforms, configuration, dependencies, testing, or deployment behaviour changes.

Every repository must have a complete `README.md` in English that lets a beginning developer understand, install, configure, use, test, build, and deploy the project without undocumented knowledge.

Include these sections when they apply:

1. Project name and one-sentence description.
2. Current status, including material limitations or unfinished areas.
3. Features and supported platforms.
4. Screenshots or a short visual demonstration stored under `docs/`.
5. Supported languages.
6. Requirements, including operating-system versions, runtimes, tools, accounts, and hardware.
7. Installation with copy-and-pasteable commands.
8. Configuration, including how to create each real configuration from its safe example.
9. Usage with at least one concrete example.
10. Development setup and relevant project structure.
11. Tests, linting, type checks, builds, and common failure messages.
12. Deployment or distribution, including shared hosting, TestFlight, the App Store, notarization, or another applicable channel.
13. External dependencies and why they are required, including account, cost, privacy, and network requirements.
14. Troubleshooting for likely beginner mistakes.
15. Known limitations and compatibility notes.
16. Contributing guidance when contributions are accepted.
17. License and third-party attribution.

Do not leave empty template headings or placeholder text in a finished README. Omit a section only when it genuinely does not apply. Keep commands, screenshots, and examples synchronized with the implementation. Supplementary documentation belongs in `docs/`, but the README remains the starting point and must link to it.
